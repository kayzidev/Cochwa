# Audit romget — 27 septembre 2026

## Conclusion

romget 0.1.0 constitue un prototype utile pour cette installation personnelle, mais ne doit pas encore être considéré comme un gestionnaire de bibliothèque fiable. Les priorités sont l'intégrité des fichiers, la sélection du bon jeu et la cohérence CLI/GUI. La refonte esthétique et l'ajout de consoles viennent ensuite.

Le handoff a été lu intégralement. Cette analyse s'appuie également sur tous les modules Python, le packaging, l'installation, les commandes exécutées, des reproductions isolées, des widgets Tkinter réellement instanciés et des sondes réseau.

Aucune correction fonctionnelle n'a été appliquée. Aucune ROM utilisateur n'a été téléchargée, modifiée, convertie ou supprimée. Steam et PCSX2 n'ont pas été lancés ni arrêtés.

## 1. État effectivement vérifié

- Python 3.14.7 ; imports requests, Pillow, tkinter et vdf disponibles.
- Wrappers CLI et GUI présents dans ~/.local/bin, avec PYTHONPATH pointant vers ce projet.
- CLI : aide et providers list opérationnels ; list retrouve les cinq ROMs décrites, dont les deux variantes GT4.
- CLI : search 'gran turismo' --limit 3 ne retourne rien et recommande le refresh historique.
- Cache historique : 51 entrées ; cache Redump : 14 959 hashes. Les deux fichiers sont récents au moment de l'audit.
- Catalogue GUI : 39 titres Top, 12 recommandés, PS2 seule console proposée.
- GUI : quatre onglets instanciés, cinq cartes de bibliothèque créées à partir du disque réel.
- Recherche Internet Archive : HTTP 200, 37 résultats annoncés pour la requête testée, deux métadonnées sommaires demandées.
- SteamGridDB : l'URL actuellement utilisée retourne HTTP 404 ; la variante avec le terme dans le chemin retourne HTTP 200 et dix résultats.
- Analyse syntaxique de tous les modules : succès. unittest discover : zéro test.
- git status échoue : aucun dépôt exploitable depuis cet environnement. Ne pas en déduire que l'utilisateur n'a aucune sauvegarde ailleurs.

### Limites de cette validation

Les tests GUI ont ouvert la vraie application Tkinter, mais suspendu le démarrage des threads externes. Ils vérifient les widgets, callbacks et géométries ; ils ne constituent pas un parcours utilisateur complet avec réseau concurrent. La capture X11 échoue avec X get_image failed : pas de capture exploitable ni de validation visuelle exhaustive du bureau Wayland. La course entre recherches a été reproduite par livraison successive de deux résultats simulés, pas par temporisation réelle du réseau.

Le test réseau vérifie la recherche et SteamGridDB, pas un téléchargement de plusieurs Go, la disponibilité de tous les fichiers, l'exécution PCSX2, ni une sauvegarde SRM. La conversion CHD a été simulée : la preuve porte sur la suppression effectuée par Python après succès, pas sur le fonctionnement de chdman.

## 2. Défauts critiques : données et sécurité des écritures

### P0 — Conversion CHD susceptible de supprimer des disques non convertis

Source : romget/providers/ia_redump.py, _convert_to_chd, lignes 294 et suivantes.

Le code choisit le premier ISO ou CUE, crée un CHD, puis supprime TOUS les .bin, .cue et .iso du dossier. Un dossier contenant plusieurs disques ou variantes perd donc les sources non converties. Le seul contrôle est que le CHD existe et n'est pas vide.

Preuve isolée : avec disc1.iso, disc2.iso et unrelated.bin, un faux convertisseur produit disc1.chd ; à la fin il ne reste que disc1.chd.

Correction : construire un plan par disque, distinguer CD/DVD et leurs pistes, convertir vers un fichier temporaire, vérifier le résultat et limiter toute suppression au groupe effectivement converti. Conserver les originaux par défaut et proposer leur retrait explicitement. Un échec doit produire un statut d'échec, pas un simple message suivi du succès général de download.

Acceptation : deux disques entrent, deux disques restent disponibles ; un échec ou une sortie invalide ne supprime rien.

### P0 — Reprise HTTP et validation finale insuffisantes

Sources : romget/api/ia.py:228 et romget/providers/ia_redump.py:260.

Le client ajoute Range puis ouvre en append sans contrôler que le serveur répond réellement 206 avec le bon Content-Range. Si le serveur retourne le fichier entier en 200, le contenu est ajouté au fragment existant. La taille attendue n'est pas vérifiée à la fin ; un fichier existant de bonne taille est accepté sans contrôler son contenu.

Preuves : abc + réponse 200 abcdef produit abcabcdef avec succès=True ; six octets reçus pour dix attendus donnent également succès=True ; XXXXXX existant est accepté pour six octets attendus.

Correction : téléchargement en .part, traitement explicite de 200/206/416, contrôle du début et de la longueur du Content-Range, vérification de taille et empreinte, ETag/Last-Modified pour éviter de reprendre une version différente, renommage atomique seulement après validation. Limiter les tentatives et permettre une reprise après redémarrage.

La sémantique des réponses partielles est définie dans [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-range-requests).

### P0 — Noms de fichiers distants utilisés comme chemins locaux

Sources : romget/gui/app.py:103 et romget/providers/ia_redump.py:267.

sanitize_dirname nettoie le titre du dossier, mais pas les noms de fichiers provenant des métadonnées. Un nom absolu remplace le préfixe ; ../ peut sortir du dossier. Les sous-dossiers légitimes ne sont pas créés non plus.

Preuve isolée : ../outside.iso écrit un fichier dans le parent de destination. Cela prouve l'absence de protection locale, pas qu'Internet Archive fournit actuellement un tel nom.

Correction : rejeter chemins absolus et traversées, vérifier le confinement après résolution, gérer les liens symboliques et créer les parents autorisés. Encoder les composants des URL ; des caractères tels que # et ? ne doivent pas modifier la requête.

### P1 — Clé API distribuée dans le code et le handoff

Une valeur de clé figure dans DEFAULT_CONFIG_TOML et à deux endroits du handoff. Elle est recopiée lors de la création d'une configuration. Sa valeur n'est pas reproduite dans cet audit.

Correction : retirer le secret du modèle et de la documentation, le garder dans la configuration locale avec droits restreints ou un stockage adapté ; prévoir sa rotation puisqu'il a été inclus dans un document transférable. La rotation n'a pas été exécutée et la configuration active est inchangée.

## 3. Recherche et identité des jeux

### P1 — CLI et GUI divergent

La CLI exploite ProviderCache et le refresh global redump-id-* ; la GUI appelle search_ps2. L'utilisateur n'obtient donc pas le même catalogue et ne peut pas compter sur la CLI pour reprendre une sélection faite dans la GUI. README et install.sh continuent de recommander le parcours qualifié d'abandonné dans le handoff.

Correction : un service de recherche et un moteur de téléchargement communs. Les providers doivent exposer recherche paginée, métadonnées et fichiers, et non exiger un index global avant toute utilisation. Maintenir une migration explicite des anciennes commandes et caches.

### P1 — « PS2 validé » mélange plusieurs preuves

search_ps2 accepte aussi un titre identique au datfile, sans MD5 correspondant, puis positionne is_ps2=True. Un hash déclaré par la source n'est par ailleurs pas un contrôle des octets téléchargés. Dans Recommandés et Top, le badge PS2 ✓ est inconditionnel, même si game.is_ps2=False.

Preuves : titre seul accepté en mode ps2_only=True ; carte non vérifiée étiquetée PS2 ✓.

Correction : séparer plateforme présumée, identification Redump par métadonnées et intégrité locale calculée. Utiliser des états explicites, notamment « identifié par titre », « hash source reconnu », « fichier vérifié » et « mod/non référencé ». Garder les mods accessibles sans leur attribuer une fausse certification.

### P1 — Sélection de variante peu fiable et packs téléchargés en bloc

find_by_title retire les informations entre parenthèses puis retourne le premier titre contenant les mots-clés, dans une liste triée par taille. À défaut il choisit le plus gros résultat. La région, les langues, la révision et le mod ne sont pas respectés. Un item IA peut contenir plusieurs jeux ou variantes : un seul hash reconnu suffit à nommer l'ensemble et tous les fichiers ISO/BIN/CUE/CHD sont téléchargés.

Correction : distinguer jeu, édition, disque, fichier et item source. Classer par titre, plateforme, région, langues, version et provenance. Afficher un écran de choix avant téléchargement avec fichiers sélectionnés et volume total. Télécharger les pistes associées au disque choisi, pas automatiquement tout l'item. Dédupliquer les sources sans fusionner Europe et Spec II.

### P2 — Heuristiques et performance

Le seuil total de 500 Mio n'est pas une preuve de plateforme et peut exclure de petites images valides. Les archives compressées sont ignorées. La requête injecte directement le texte dans la syntaxe Solr ; parenthèses et opérateurs peuvent en changer le sens. Les erreurs metadata sont fréquemment avalées et deviennent « aucun résultat ».

Recommandés et Top démarrent dès la construction de l'application, même invisibles : 51 recherches de titres, chacune pouvant demander jusqu'à 60 métadonnées, soit jusqu'à 3 060 requêtes metadata avant les jaquettes, hors retries. C'est une borne calculée à partir du code, pas un nombre mesuré en production.

Correction : afficher immédiatement le catalogue local ; résoudre les sources au clic ou à l'ouverture d'un onglet ; partager cache, sessions HTTP et requêtes identiques ; plafonner le travail global ; annuler les recherches périmées. Ajouter pagination réelle, tri de pertinence, filtres région/langue/version, recherche série et retour distinguant panne, restriction d'accès et absence de résultat.

## 4. GUI : bugs et parcours à améliorer

### P1 — Erreurs différées et cycle de vie des widgets

Les lambdas créées dans except Exception as e réutilisent e après la sortie du bloc. Python supprime cette variable : le callback peut échouer avec NameError au lieu de montrer le problème initial. Reproduit sur SearchTab._search_worker ; le motif existe aussi dans app.py.

Les résultats n'ont pas d'identifiant de génération : une ancienne recherche peut s'ajouter aux résultats d'une nouvelle. Les jaquettes peuvent revenir après destruction d'une carte ; changer la liste détruit le widget sans arrêter son worker. PhotoImage est créé dans les workers de jaquettes ; les appels à after partent aussi des workers et dépendent de la boucle Tcl/Tk.

Correction : workers limités au réseau/disque et aux données ; queue d'événements consommée par root.after depuis le thread GUI ; identifiants de tâche/génération ; annulation à la fermeture ; contrôle des widgets existants ; capture immédiate du texte d'erreur. Tkinter dispose d'un mécanisme de transfert entre threads, mais dépend de l'état de l'interpréteur et de sa boucle : éviter de résumer cela à « tous les appels hors thread principal échouent ». Voir [modèle de threading Tkinter](https://docs.python.org/3/library/tkinter.html#threading-model) et [portée des exceptions Python](https://docs.python.org/3/reference/compound_stmts.html#the-try-statement).

### P1 — Installé ne signifie actuellement pas jouable

is_installed teste seulement l'existence du dossier nommé après le jeu : un dossier vide est installé, un téléchargement incomplet peut sembler jouable, une ROM à la racine peut ne pas être reconnue. Recherche ne fournit pas on_play, donc son bouton peut rester Télécharger même si le jeu est reconnu installé. play_game choisit le premier fichier rencontré ; main_rom n'est pas utilisé.

Correction : index local partagé CLI/GUI, états absent/partiel/vérifié/prêt, identité stable et chemin de lancement déterministe. Gérer ISO isolé, sous-dossiers, CUE avec pistes et jeux multi-disques. Vérifier les chemins et afficher les erreurs PCSX2 au lieu de supprimer stdout/stderr sans diagnostic.

### P1 — Téléchargements concurrents sans supervision

Chaque clic crée un thread daemon. Aucun verrou par destination, limite globale, pause, annulation ou reprise de session. Plusieurs tâches écrasent la même barre de statut ; fermer la fenêtre interrompt les workers. mkdir s'effectue avant le bloc d'erreur du worker. Aucun précontrôle d'espace libre ou de point de montage.

Correction : gestionnaire commun avec file persistante, verrou de destination, progression par fichier/jeu, débit, volume restant, erreurs récupérables et espace requis. Identifier l'absence du disque prévu avant de créer des dossiers sur un autre volume.

### P2 — Ergonomie et lisibilité

Constats du code et des widgets : quatre colonnes fixes, pas de liaison explicite de molette sur les canvas, titre tronqué à 60 caractères, statuts et tailles en gris sombre, état du bouton PS2 ✓ inchangé après bascule. À 900×600, la grille bibliothèque demande 848 pixels pour un canvas de 845 ; à 1100×720, le canvas a 1 045 pixels mais la grille n'utilise que 848. Ce sont des mesures de widgets, pas une estimation visuelle.

Améliorations : colonnes adaptatives, molette Linux/trackpad, navigation clavier et focus visibles, meilleur contraste, titre complet accessible, fiche détail, filtre PS2 explicite, états vide/chargement/erreur différenciés. Ajouter recherche/tri local dans la bibliothèque, paramètres persistants, actions ouvrir le dossier et vérifier le jeu, onglet Téléchargements et notifications non bloquantes.

Une réécriture dans un autre framework n'est pas nécessaire pour résoudre ces problèmes. Conserver Tkinter pour le prochain palier réduit le périmètre de changement.

## 5. Jaquettes, cache et configuration

### P1 — Endpoint SteamGridDB incorrect dans l'implémentation

romget/api/steamgriddb.py appelle /search/autocomplete?term=… : HTTP 404 lors de la sonde réelle. /search/autocomplete/Gran%20Turismo%204 retourne HTTP 200, JSON et dix entrées avec la même configuration d'authentification. Les jaquettes en cache peuvent masquer cette panne.

Correction : terme encodé dans le chemin, gestion des réponses et choix de l'identité exacte. Ajouter un test de contrat. Les résultats de recherche GUI n'ont de toute façon aucun chargement de jaquette actuellement.

Autres améliorations : cache par ID/version plutôt que titre tronqué et nettoyé, écritures atomiques, déduplication des téléchargements, cache négatif temporaire, invalidation d'une image corrompue, taille mémoire bornée, ratio de jaquette conservé. Les jaquettes 600×900 sont actuellement redimensionnées en 180×250, ce qui déforme leur ratio. Permettre un choix manuel pour les mods.

### P1 — Fallback Redump périmé inopérant

load() réessaie _load_cache() après l'échec réseau mais cette méthode rejette toujours le TTL dépassé. La promesse « cache même périmé » n'est donc pas tenue. Reproduit : cache valide mais ancien + réseau indisponible = False.

En cas d'échec, les lookups peuvent retenter load à répétition. Le singleton n'est pas protégé contre les chargements concurrents ; la GUI peut annoncer « Datfile chargé » sans contrôler le booléen retourné. Les écritures JSON ne sont pas atomiques. Le datfile est récupéré en HTTP et les limites de taille/structure ne sont pas contrôlées.

Correction : état chargé/absent/périmé/échec distinct, un seul chargement à la fois, période d'attente après échec, lecture stale autorisée explicitement, publication atomique d'un index complet, provenance et intégrité contrôlées. Vérifier la disponibilité d'une source HTTPS avant toute migration d'URL.

### P2 — Configuration non persistante et partiellement ignorée

Changer dossier modifie l'objet en mémoire, pas config.toml. Config.load(custom_path) crée le fichier par défaut au lieu du chemin demandé s'il manque ; FileNotFoundError reproduit. ps2_dir n'expanse pas ~. Les options provider datfile_url/cache_dir sont utilisées par le provider CLI mais contournées par les constantes de l'API GUI.

Correction : service unique de configuration avec chemin explicite, validation TOML/type/valeurs, expansion des chemins, écriture atomique, paramètres GUI persistants et options --config/--cache-dir. Respecter les emplacements XDG et rendre le script PCSX2 configurable.

## 6. CLI, installation et maintenance

- Fournir la même recherche, sélection de fichiers, vérification et reprise que la GUI.
- Ajouter --json et une sortie stderr séparée ; codes de retour stables pour panne réseau, configuration, fichier absent et conversion échouée.
- Valider limit/offset ; permettre annulation Ctrl+C propre, inspection d'un résultat, progression et mode de prévisualisation sans écriture.
- Ajouter doctor : version Python, dépendances GUI, dossier/montage, espace, émulateur, chdman, SRM, état des caches et connectivité sur demande. Ne jamais afficher la clé.
- L'installation déclarée oublie Pillow et l'entrée romget-gui ; tkinter dépend du système. vdf est déclaré mais non utilisé par les sources actuelles.
- install.sh appelle pip non présent dans l'environnement décrit, tente --break-system-packages et masque les erreurs du premier essai. Prévoir une installation reproductible en environnement virtuel et documenter aussi le mode wrapper réellement utilisé.
- README est orienté vers le provider abandonné. Mettre à jour commandes, limites, installation et distinction entre ouvrir SRM et réellement ajouter des jeux.
- Le champ license annonce MIT sans fichier LICENSE visible ; compléter si c'est bien la licence souhaitée.
- Des imports et annotations obsolètes subsistent, dont ImageTk.PhotoImage alors qu'ImageTk n'est pas importé. Ce n'est pas un crash à l'import grâce aux annotations différées, mais nuit à l'outillage.
- Mettre en place versionnement et sauvegarde si aucun dépôt n'est disponible ailleurs ; ajouter lint, contrôles de types ciblés et tests automatiques sur les chemins critiques.

## 7. Intégration Steam : garder une portée réaliste

trigger_srm_reparse ouvre SRM et imprime des instructions : il ne réalise pas lui-même un parse ni une écriture dans Steam. La GUI actuelle n'expose pas cette action après téléchargement. Le CLI ignore le booléen d'échec de SRM dans download --add-steam.

Amélioration immédiate : action « Ouvrir Steam ROM Manager », instructions visibles, résultat honnête, conservation des variantes/mods et contrôle de la configuration du parser. Préserver la règle de ne pas arrêter Steam automatiquement.

Une intégration directe shortcuts.vdf est une évolution ultérieure : sauvegarde, profil explicite, identifiants stables, écriture sûre, idempotence et coexistence avec SRM doivent être traités avant d'en faire un raccourci pratique.

## 8. Architecture cible et ordre de réalisation

Ne pas multiplier les fonctionnalités avant de partager les services entre CLI et GUI. Cible proposée : modèles Game/Edition/Disc/RemoteFile/InstalledGame ; services SearchService, DownloadManager, LibraryService, ArtworkService et SteamIntegration ; clients HTTP injectables ; configuration et cache communs. Une base SQLite devient pertinente pour les tâches persistantes et l'index local, sans être indispensable au premier correctif.

| Lot | Livrable | Critère de sortie |
|---|---|---|
| 1 — Intégrité | Reprise HTTP, .part, hashes, chemins confinés, conversion conservatrice, traitement des secrets | Aucune corruption annoncée comme succès ; aucun fichier hors destination ; aucun disque non converti supprimé |
| 2 — Cohérence | API commune CLI/GUI, sélection édition/disque, badges honnêtes, correction SteamGridDB et cache Redump | Même recherche dans les deux interfaces ; choix de région/mod conservé ; panne clairement signalée |
| 3 — Utilisation quotidienne | File persistante, événements GUI sûrs, index local, paramètres, grille adaptative, jaquettes | Deux recherches rapprochées ne se mélangent pas ; fermeture/reprise et disque absent gérés |
| 4 — Distribution | Installation reproductible, documentation, doctor, tests et CI | Une installation propre lance CLI et GUI et passe les scénarios critiques |
| 5 — Extensions | Autres consoles, préférences avancées, intégration Steam enrichie | Ajout d'une console sans duplication du téléchargement ni régression PS2 |

Multi-console, drag-and-drop et intégration Steam directe restent des évolutions utiles, mais ne résolvent pas les défauts de fiabilité actuels.

## 9. Plan de validation à conserver

Tests prioritaires : serveur ignorant Range ; 206 avec mauvais offset ; 416 ; interruption et reprise ; modification distante ; taille/hash incorrect ; doublon concurrent ; manque d'espace ; chemins absolus, ../ et liens symboliques ; CUE multi-pistes et dossiers multi-disques ; conversion échouée ; cache corrompu/périmé ; refus API/timeout/429 ; sélection région/mod ; deux recherches en concurrence ; fermeture et refresh pendant chargement de jaquettes ; installation neuve ; configuration invalide ; échec PCSX2 et SRM.

Les scripts d'audit présents reproduisent des défauts avec petites fixtures ; ils ne sont pas une suite qui valide le comportement correct. Après correction, transformer les reproductions pertinentes en tests de non-régression.

## 10. Preuves et reprise

- CURRENT_STATE.md : point de reprise durable.
- audit/probe.py : reproductions isolées ; option --gui pour instancier les widgets réels.
- audit/results.json et audit/results-gui.json : résultats observés.
- audit/network_probe.py et audit/network-results.json : sondes de métadonnées et codes HTTP.

Exécution locale depuis la racine : PYTHONPATH=. python3 audit/probe.py ; pour la GUI, ajouter --gui. Le test GUI lit le dossier PS2 de cette installation mais neutralise ses threads et n'écrit que dans des fixtures temporaires et les sorties d'audit. La sonde réseau lit la clé locale pour la transmettre uniquement à SteamGridDB, sans l'imprimer.
